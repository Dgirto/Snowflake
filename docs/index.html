¿Qué es y para qué sirve?

El conector Snowflake permite que el agente de Ruvic consulte tu data warehouse de Snowflake en modo solo lectura: puede leer y analizar información, pero nunca modificarla. Una vez configurado, puedes pedirle al agente cosas como:

  • "Muéstrame las ventas por región del último trimestre en la base VENTAS."
  • "¿Qué bases de datos y esquemas puedo consultar?"
  • "Antes de correr esta consulta sobre la tabla de pedidos, dime cuánto va a tocar."

Operaciones soportadas:

Operación Qué hace
db.execute_query Ejecuta una consulta SQL de solo lectura (SELECT o WITH) y devuelve las filas (máximo 10 000 por consulta)
db.list_databases_and_schemas Lista las bases de datos y esquemas visibles para el usuario configurado
db.estimate_query_cost Estima el alcance de una consulta con EXPLAIN antes de ejecutarla, sin consumir cómputo del warehouse
Solo lectura, por diseño El conector valida en código que toda consulta empiece con SELECT o WITH; cualquier otra sentencia (INSERT, UPDATE, DELETE, CREATE, DROP, MERGE) se rechaza antes de llegar a Snowflake. Además, el usuario dedicado solo tiene permiso SELECT: hay dos barreras independientes.

Prerrequisitos

  • Una cuenta de Snowflake activa, con un identificador de cuenta válido (visible en la URL de Snowsight, ej. xy12345.us-east-1).
  • Acceso con rol SECURITYADMIN o equivalente (permiso para crear usuarios y roles), solo durante la configuración inicial.
  • Un warehouse (almacén de cómputo) existente o la posibilidad de crear uno pequeño y dedicado.
  • Los datos de conexión: cuenta, warehouse, base de datos y esquema por defecto que el agente va a consultar.

Configuración en el fabricante

Vas a crear un rol y un usuario dedicados de solo lectura para Ruvic. No reutilices un usuario administrador ni el de tu aplicación: un usuario dedicado permite auditar la actividad del agente, limitar el acceso al mínimo y controlar los costos de cómputo con un warehouse propio.

  1. Conéctate a Snowflake como administrador. Usa Snowsight o SnowSQL con un rol con privilegios para crear roles y usuarios (ej. SECURITYADMIN).
  2. Crea el rol de solo lectura. Este rol solo tendrá permisos de uso y lectura, nunca de escritura ni administración: 
    CREATE ROLE ruvic_reader;
  3. Asigna un warehouse mínimo dedicado. Usa un warehouse pequeño (idealmente XSMALL) exclusivo para Ruvic, así controlas el costo de cómputo por separado del resto de tu organización: 
    CREATE WAREHOUSE IF NOT EXISTS ruvic_wh
  WAREHOUSE_SIZE = 'XSMALL'
  AUTO_SUSPEND = 60
  AUTO_RESUME = TRUE;

GRANT USAGE ON WAREHOUSE ruvic_wh TO ROLE ruvic_reader;
  4. Otorga acceso de solo lectura a las bases y esquemas a exponer. Repite para cada base de datos/esquema que el agente deba poder consultar (el ejemplo usa ventas.public): 
    GRANT USAGE ON DATABASE ventas TO ROLE ruvic_reader;
GRANT USAGE ON SCHEMA ventas.public TO ROLE ruvic_reader;
GRANT SELECT ON ALL TABLES IN SCHEMA ventas.public TO ROLE ruvic_reader;
GRANT SELECT ON FUTURE TABLES IN SCHEMA ventas.public TO ROLE ruvic_reader;
    Nota El GRANT ... ON FUTURE TABLES hace que las tablas creadas más adelante en ese esquema también sean legibles por Ruvic sin repetir el GRANT.
  5. Crea el usuario dedicado y asígnale el rol. Elige una contraseña fuerte (mínimo 16 caracteres, generada aleatoriamente) y guárdala: la usarás en el formulario de Ruvic (campo Contraseña). 
    CREATE USER ruvic_reader_user
  PASSWORD = 'CAMBIA_ESTA_CONTRASEÑA'
  DEFAULT_ROLE = ruvic_reader
  DEFAULT_WAREHOUSE = ruvic_wh
  MUST_CHANGE_PASSWORD = FALSE;

GRANT ROLE ruvic_reader TO USER ruvic_reader_user;
  6. Configura la network policy (opcional pero recomendado). Si tu organización exige restringir el acceso por IP, crea o actualiza una network policy de Snowflake con las IPs de salida de la plataforma Ruvic y asígnala al usuario dedicado: 
    CREATE NETWORK POLICY ruvic_policy
  ALLOWED_IP_LIST = ('IP_DE_RUVIC/32');

ALTER USER ruvic_reader_user SET NETWORK_POLICY = 'ruvic_policy';
    [ Captura: Network Policies en Snowsight (Admin → Security) con la IP de Ruvic — reemplazar por assets/img/snowflake-network-policy.png ]
  7. Verifica el usuario desde fuera de tu organización. Con SnowSQL o el conector Python, confirma que el usuario puede autenticarse y consultar con el rol y warehouse asignados: 
    snowsql -a xy12345.us-east-1 -u ruvic_reader_user -r ruvic_reader -w ruvic_wh -d ventas -s public -q "SELECT 1"
    Si responde 1, el fabricante quedó listo. Anota estos valores para la sección de configuración en Ruvic: cuenta, usuario, contraseña, warehouse, base de datos, esquema y rol.

Permisos requeridos

Principio de mínimo privilegio: el usuario de Ruvic solo necesita estos permisos. No otorgues roles de escritura (INSERT, UPDATE, DELETE) ni de administración (CREATE, DROP, GRANT).

Permiso Para qué sirve
USAGE (warehouse) Ejecutar cualquier consulta; el cómputo se cobra por tiempo de warehouse activo
USAGE (base de datos / esquema) Acceder a los objetos de la base y el esquema configurados
SELECT (tablas / vistas del esquema) Leer datos con db.execute_query y generar el plan de ejecución con db.estimate_query_cost

No se otorgan permisos de escritura ni de administración: el rol ruvic_reader nunca debería incluir INSERT, UPDATE, DELETE, CREATE, DROP ni GRANT. Aunque se otorgaran por error, el conector rechaza en código cualquier sentencia que no empiece con SELECT o WITH.

Configuración en Ruvic

Entra a Settings → Conectores, busca la tarjeta Snowflake y pulsa Configurar. Diligencia el formulario con los valores que obtuviste en la sección anterior:

Campo del formulario Valor
Cuenta de Snowflake Identificador de cuenta, visible en la URL de Snowsight (ej. xy12345.us-east-1)
Usuario ruvic_reader_user (o el nombre que hayas elegido)
Contraseña La contraseña creada en el paso 5 de la sección anterior. Se guarda cifrada como secreto: la interfaz no volverá a mostrarla
Warehouse ruvic_wh (o el warehouse dedicado que hayas creado)
Base de datos Nombre de la base de datos a consultar (ej. ventas)
Esquema Esquema por defecto; PUBLIC si no lo cambiaste
Rol Opcional. ruvic_reader; si se omite, se usa el rol por defecto del usuario
Timeout de conexión (segundos) Opcional; 30 segundos por defecto

Guardar y luego pulsa Probar conexión — la plataforma se conectará a tu cuenta de Snowflake y confirmará que las credenciales, el warehouse y la red funcionan.

[ Captura: formulario del conector Snowflake en Settings → Conectores — reemplazar por assets/img/snowflake-form.png ]

Verificación

  1. Test de conexión exitoso. El botón Probar conexión debe responder: "Conexión exitosa a Snowflake (tu-cuenta)". La tarjeta del conector cambia a estado Configurado.
  2. Prueba con el agente: listar bases y esquemas. Abre una conversación nueva con el agente y pídele:
    "Lista las bases de datos y esquemas de Snowflake que puedo consultar."
    El agente debe responder con el listado real de bases y esquemas visibles para el usuario configurado.
  3. Prueba con el agente: consulta de solo lectura. Pídele una consulta simple sobre una tabla que sepas que existe:
    "Ejecuta un SELECT con LIMIT 10 sobre la tabla de pedidos y muéstrame el resultado."
    Si el agente devuelve filas reales, el conector quedó operativo de punta a punta. Puedes pedirle además que estime el alcance de una consulta antes de correrla ("¿cuánto va a tocar esta consulta?") para confirmar que estimate_query_cost también funciona.

Solución de problemas

Mensaje / síntoma Causa probable y solución
"Autenticación fallida: Credenciales inválidas o sin permiso suficiente sobre esta cuenta de Snowflake." Usuario, contraseña o rol incorrectos, o el usuario no tiene el rol asignado. Verifica el paso 5 de la configuración en el fabricante y vuelve a guardar el formulario (deja la contraseña vacía para conservar la anterior o escribe la nueva para reemplazarla).
"No se pudo alcanzar la cuenta '...' " o timeout de red El identificador de cuenta está mal escrito (revisa el formato, ej. xy12345.us-east-1) o la network policy de Snowflake bloquea las IPs de Ruvic. Revisa el paso 6 de la configuración en el fabricante y aumenta el timeout de conexión si tu red es lenta.
Warehouse suspendido o sin acceso ("Warehouse ... cannot be used because it is suspended" o error de permisos al ejecutar) El warehouse configurado no existe, no tiene AUTO_RESUME habilitado o el rol no tiene USAGE sobre él. Repite el paso 3 de la configuración en el fabricante (crear/otorgar el warehouse) y confirma el nombre exacto en el campo Warehouse del formulario.
El agente lista bases y esquemas pero falla al leer una tabla ("Consulta SQL inválida" o error de permisos) Falta el GRANT SELECT sobre esa tabla/esquema (tablas creadas antes del GRANT ... ON FUTURE TABLES), o la consulta no empieza con SELECT/WITH y fue rechazada por diseño. Repite el paso 4 de la configuración en el fabricante para ese esquema.
El conector aparece "Sin configurar" tras guardar Algún campo obligatorio quedó vacío. Ábrelo de nuevo y completa cuenta, usuario, contraseña, warehouse, base de datos y esquema (el rol y el timeout son opcionales).

Preguntas frecuentes y notas de seguridad

¿El agente puede modificar o borrar datos?

No. Dos barreras independientes lo impiden: el conector valida en código que toda consulta empiece con SELECT o WITH (cualquier otra sentencia se rechaza antes de llegar a Snowflake), y el rol ruvic_reader solo tiene permiso SELECT sobre los esquemas expuestos.

¿Dónde queda guardada la contraseña?

Como secreto en el almacén de credenciales de la plataforma, asociado a tu usuario. La interfaz nunca vuelve a mostrarla; solo indica "definida". Para cambiarla, escribe una nueva en el formulario; para conservarla al editar otros campos, deja el campo vacío.

Rotación de credenciales

Recomendado cada 90 días o según tu política: cambia la contraseña en Snowflake (ALTER USER ruvic_reader_user SET PASSWORD = '...'), actualízala en el formulario del conector y pulsa Probar conexión.

¿Qué hago si la contraseña se compromete?

  1. Cambia la contraseña en Snowflake de inmediato (ALTER USER ruvic_reader_user SET PASSWORD = '...') o desactiva el usuario (ALTER USER ruvic_reader_user SET DISABLED = TRUE).
  2. Revisa la actividad reciente del usuario en SNOWFLAKE.ACCOUNT_USAGE.LOGIN_HISTORY y QUERY_HISTORY.
  3. Actualiza la nueva contraseña en el formulario del conector.

¿Por qué usar un warehouse dedicado y pequeño?

Cada consulta que ejecuta el agente consume tiempo de cómputo del warehouse configurado, y eso genera cargos reales según tu plan de Snowflake. Un warehouse XSMALL dedicado a Ruvic, con AUTO_SUSPEND corto, aísla ese costo del resto de tu organización y facilita monitorearlo. Nota: estimate_query_cost usa EXPLAIN, que no ejecuta la consulta ni genera cargos, pero execute_query sí.

Buenas prácticas Usa siempre un usuario y rol dedicados de solo lectura; asigna un warehouse pequeño exclusivo para controlar costos; restringe el acceso con una network policy si tu organización lo exige; no expongas esquemas con datos sensibles que el agente no necesite; y evita compartir la contraseña por canales no seguros.
